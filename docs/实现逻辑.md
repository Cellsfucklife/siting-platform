# 平台实现逻辑

一次请求处理一个配送节点。输入是一个片区的三张表，输出是两样东西：这个节点的模糊位置范围，和它该配多大。

## 数据怎么进来

页面有五个输入端口，只有「小区」是必填。表格文本走 `webapp/forms.py` 的行解析器，Excel 走 `webapp/tables.py`，两条路最终都变成同样的行列表，所以报错文案、默认值、校验规则完全一致。

坐标允许两种写法：经纬度，或以片区中心为原点的相对米制。后者在内部换算成一个固定伪原点（39.9, 116.4）附近，换算只做平移和缩放，两点间距离不变，结果页会把坐标还原回用户自己的米制。

Excel 读取做了四件事：识别表头（第一行后几列不是数字就当表头）、按列名别名重排（`小区名/名称/id`、`纬度/lat`、`经度/lng`、`日件量/qty` 都认）、多工作表时按关键词挑表、超范围的值直接报错。距零表的两列都叫名称，所以它按方向匹配（小区/起点/from → 场地/终点/to → 分钟），不走通用重排。

校验按顺序执行，前一步出错就不再往下判断：行解析错误 → 空表 → 坐标范围（含纬度经度填反的自动纠正）→ 样本量（少于 3 个小区且无场地时拒绝）。这样报错总是最具体的那条。

## 原始流水先做一次推演

如果给的是逐条流水（小区, 日期, 件量），选址前先跑一层拟合。日期支持按天、周、月、年四种粒度，也认 `2025-01-03`、`2025/1/3`、`2025年1月`、`2025` 这几种写法。

模型是最小二乘的线性方程：

```
y_t = β0 + β1·t + Σ 周内哑变量 + Σ 月度哑变量 + ε
```

t 以年为单位，所以 β1 直接是年增量。三个约束决定它能识别出什么：

- 周内系数只在按日聚合、且跨度超过 20 天时可识别。
- 月系数只在跨度满两年时可识别。一年之内，月度哑变量会把趋势吃光——这是行数不足时最容易踩的坑，代码里按 730 天硬性把关。
- 参数个数逼近样本数时退化为「截距 + 趋势」，不再加季节项。

拟合用迭代剔除的稳健版本：先全量拟合，剔除残差超过 2.5 倍标准差的点，再重解，最多四轮。大促日是少数极端点，不剔除会把趋势项拉偏——同一份合成数据上，不剔除时年增长估成 0.147（真值 0.10），剔除后是 0.107。

推演产出六组指标：水平项（末期拟合值，折算成日均）、趋势项（年增长率）、周内系数（七项，归一化到均值 1）、月系数（跨度够才有）、峰值系数、波动项（剔除大促后的残差变异系数）。

峰值系数取「实际值 ÷ 当时的趋势值」，不取「最大值 ÷ 全局均值」——后者会把多年的增长算进峰值。窗口里若没有覆盖大促，观测峰值往往低于默认的 1.6，这时保留 1.6 并提示补数，宁可高估也不低估容量。

最后把件量换成**设计年日均**：`末期水平 × (1+年增长)^(设计年偏移 − 0.5)`，减 0.5 是取该年年中，用年均值去配容量比用年末值稳妥。这一步替换掉输入里的件量原值，峰值系数也一并替换，其余参数不动。

## 数据画像决定启用几个方法

| 画像 | 条件 | 启用 |
|---|---|---|
| L3 完整 | 小区 + 场地 + 距离矩阵 + 至少 3 项评分 | M1 M2 M3 M4 |
| L2 标准 | 小区 + 场地 | M1 M2 M3 M4（距离退化估算） |
| L1 精简 | 只有小区 | M1 M3 |
| L0 极限 | 只有场地 + 代理件量 | M4 |

融合权重等于方法先验乘以数据质量分。M2 的先验 0.34（含约束，信息最多），其余 0.22。只剩一个方法时，隶属度场开 0.65 次方放宽，总置信度封顶 0.45；只剩两个时封顶 0.72。这条规则挡住的是"单方法自说自话"。

## 四个方法各输出一张隶属度场

四个方法不直接争位置，各自给出一张 `μ(x) ∈ [0,1]` 的场，表示每个格点"可不可以建"。

**M1 连续重心。** 最小化 `Σ 件量 × 距离`，用 Weiszfeld 迭代求解，参考解用 `scipy.optimize` 的 Nelder-Mead 对照。它不返回"中心加固定半径"，而是把整张目标函数地形取出来，令 `μ = exp(−(目标值/最优值 − 1)/β)`，β = 0.045。这样模糊区的宽度由成本曲线自己的曲率决定，不用拍一个核宽。

**M2 离散候选。** 位置用 p-中值（`spopt.locate.PMedian`，p=1，CBC 精确求解），档位用 CFLP（`PuLP` 建模，含容量与场地面积约束）。另跑 300 次扰动（件量 ±10%、距离 ±5%），统计每个候选被选中的频率，用这个频率做高斯混合，得到 ε-最优集合。p-中值与 CFLP 选出不同位置时不判矛盾，输出一条租金敏感度：这个片区的租金梯度足以改变选址。

**M3 核密度。** `sklearn.KernelDensity`，带宽按 Scott 规则并按片区面积缩放，输出归一化的需求密度。

**M4 多准则。** 熵权确定指标权重，TOPSIS 算贴近度，得分取 softmax 后作为候选的混合权重。它只看属性（可达性、竞争、可租性、可扩展），不看距离，所以是与前三个方法正交的证据源。

## 融合成唯一的模糊中心

```
μ(x) = Σ wₘ · μₘ(x)
中心 = 融合场峰值邻域（5×5 格）的质量加权质心
r68 / r90 = 以中心为原点，隶属度质量累积到 68% / 90% 的距离
多峰 = 检测到第二个 ≥0.55 的局部极大，且距主峰 >300 m
```

给范围而不给点，是因为位置本身就带误差：数据有 ±10%，方法假设也各不相同。把误差显式画出来，比给一个看起来精确的坐标更诚实。多峰告警对应的是实际情况——两片需求分开的地方，一个节点盖不住。

## 容量是算出来的

四步，全部有公式，没有一处拍系数。

```
① 服务圈件量    r = 服务圈分钟 × 接驳速度（默认 10 min × 12 km/h = 2000 m）
                S = 圈内各小区日件量之和
② 峰值折算      峰值日 = S × 峰值倍数(1.6)
                峰值小时 = 峰值日 × 24 点曲线最大占比
③ 四项容量      储存单元 = 峰值日 × 自提比例 / 单格口日周转(1.8)
                人力 = 分拣(⌈S/1200⌉) + 窗口
                窗口用 M/M/c 的 Erlang-C 反解最小 c，约束 P(排队) ≤ 0.10 且 平均等待 ≤ 180 s
                车辆 = ⌈S / 单车日能力(160)⌉
                充电桩 = ⌈车辆 × 90 min / 单桩日可用 900 min⌉
④ 档位与区间    档位 = 同时满足日通过能力、峰值小时能力、储存单元三项的最小档
                蒙特卡洛 250 次（件量 ±10%）→ 日件区间、档命中率、边界风险
```

档命中率低于 0.75 时标记"档位处于边界"。意思是需求正压在两档之间，抽样换一批就会跳到下一档，应当按高档预留并设扩容触发线。

## 结果互相验证

四层检查，任何一层不过都会压低总置信度。

| 层 | 比什么 | 合格线 |
|---|---|---|
| 实现间 | 自研实现与参考实现是否同一答案 | 距离 ≤60 m / 参考解落在 ε-最优前三 / 场相关系数 ≥0.98 |
| 方法间 | 各方法中心是否落在融合 90% 区内；模糊区形状相似度（Bhattacharyya） | 综合 ≥0.75 为 high |
| 容量间 | 各方法中心对应同一服务圈的件量离散度 | ≤25% |
| 结构 | 件量 ×1.2 后容量单调不减 | 必须通过 |

形状相似度用 Bhattacharyya 而非掩膜交集，因为各方法核宽度天然不同，硬阈值会系统性惩罚窄场。

## 目前做不到的

1. 距离默认用直线乘 1.35，接真实路网需要高德或 OSRM。
2. 档位表是内置的 7 档示例值，报绝对投资前必须换成实际台账。
3. CFLP 的固定成本是代理值（档位系数乘租金），不是报价。
4. 分时到达曲线用内置城市曲线，页面还没开口接收真实曲线。这一项对峰值小时、人力、档位影响最大。
5. 容量未包含二次分拣与退货暂存，峰值校准时要补进工序表。
6. M4 没有第三方等价实现，只做权重扰动，不进"实现间一致性"统计。
