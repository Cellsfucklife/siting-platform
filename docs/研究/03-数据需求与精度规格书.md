# 数据需求与精度规格书（含容量配置内生化改造）

> 三份文件的关系：
> ①《选址模型全景综述》= 有哪些模型；②《选址增强理论技术清单》= 能加什么；
> ③ 本文 = **为了让①②跑起来，要什么数据、要多准、跟谁签、拿不到怎么办**，以及**如何让同一个模型顺带吐出容量配置**。

---

## 0. 三条定调原则（先立规矩，再列清单）

### 原则一：数据分"面"和"参数"，获取策略完全不同

| 类别 | 特征 | 典型 | 获取方式 |
|---|---|---|---|
| **面（Field）** | 覆盖全域、样本量大、决定"选在哪" | 社区级日件量、分时段分布、路网 OD、现有网点台账、人口栅格 | **必须签约或购买**，自建不可能 |
| **参数（Parameter）** | 点数少、只需几十个样本、决定"建多大" | 单柜周转率、平均滞留时长、单件处理工时、自提意愿比例、单车日配送能力 | **自建抽样 + 踏勘 + 问卷**，1–3 万元搞定 |

**这条原则直接回答了你的问题**：小数据量的参数类不用管，你们自己做；真正要谈合同的是"面"，一共就 6 个包。

### 原则二：精度要求由"决策翻转阈值"反推，不追求越高越好

不要问"数据要多准"，要问"**误差多大时，选点或容量档位会翻**"。三类阈值：

- **覆盖判定阈值**：服务半径 5 分钟步行 ≈ 300–400 m。位置误差只要 ≤ 半径的 10%（30–40 m），就不会误判覆盖。
- **容量跨档阈值**：容量档位是离散的（如柜组 100/200/400/800 格）。件量误差只要不把某点从一档推到下一档，结论就不变——通常 ±10% 内不跨档。
- **排序翻转阈值**：点位 A/B 的总成本差 <数据误差带来的成本差时，排序不可信。这个靠敏感性分析测，不靠数据精度硬扛。

**直接结论：面数据 ±10%、位置 ±30 m、时段结构 ±20%，就足以支撑正确决策；再往上买精度是浪费预算。**

### 原则三：每种数据都要有"拿不到的 B 计划"

赛事方案最大的风险不是模型不精，是数据没到手。每个必签包都要配 B 计划（见第 6 节），否则整份方案建立在一个"假设能拿到"的承诺上。

## 2. 按模型的输入清单（不同实现方法要什么）

| 实现方法 | 必需输入 | 精度底线 | 缺了会怎样 |
|---|---|---|---|
| **重心法 / 交叉中值** | 需求点坐标、需求量、单位运价（D1、D4、D13） | 坐标 ±50 m 即可 | 结果落在不可建地块，只能当初始解 |
| **集合覆盖 SCP** | 覆盖矩阵 `a_ij`（D6 路网 + D12 限行 + 服务半径标准）、候选点集（D8） | 时间矩阵 ±15%；候选点必须真实可建 | 算出的"最少点数"不可执行 |
| **最大覆盖 MCLP** | 上述 + 需求权重 `h_i`（D1）、p 或预算 | `h_i` ±10%，聚合粒度 ≤社区 | 覆盖率乐观偏高（因为把需求点当质点） |
| **p-中值** | 路网距离矩阵、权重、p（D6、D1） | 距离 ±5% | 总里程低估（直线距离会低估 20–40%） |
| **CFLP（含容量）** | + 固定投资 `f_j`（D13、D8）、容量 `Q_j`（D4、D17、D18） | 投资 ±15%，容量**精确** | 开点数量失真，容量约束失效 |
| **两级 / 轴辐** | + 两层候选、两套运价（D15）、层间容量 | 运价 ±10% | 层级收益（折扣）消失，退化成单层 |
| **LRP / 2E-LRP** | + 车队参数、时间窗（D19、D20）、客户点 | 单车能力 ±10% | 路径不可行，"时效达成"变空话 |
| **两层随机 / 鲁棒 / DRO** | + 情景集（D1 历史分布、D3 大促系数） | 样本量 ≥12 个月、≥30 个同类社区 | 不确定性集拍出来，结论不可信 |
| **双层规划（自提选择）** | + 选择模型标定数据（D16、D2）、竞品（D24） | 意愿比例 ±5pp，系数符号正确 | "建了没人用"无法预判 |
| **MCDM（AHP/TOPSIS）** | + 指标打分表（D8、D13、D22、D24、D9） | 打分可复现，权重有依据 | 排序主观，被质疑"专家拍脑袋" |
| **GIS 空间分析 / 2SFCA** | + POI、人口栅格、路网（D6、D9） | 人口 ±5%，路网 ≤5% | 可达性图好看但不能决策 |
| **复杂网络韧性** | 拓扑 + 流量（D1、D4） | 拓扑准确即可 | 关键节点识别错 |
| **MGWR 空间异质** | 区级因变量/自变量面板（D1、D9） | 样本 ≥50 个空间单元 | 系数不可估 |
| **仿真 / 数字孪生** | + 到达过程、交通流、设备参数（D2、D11、D17–D20） | 分布族正确优先于精度 | 仿真结果不可信，沦为动画 |
| **预测+优化（GNN）** | + 长时序多源数据（D1、D2、D10、D11） | ≥12 个月、缺失 <5% | 预测误差传导到选点 |

**读法**：越往下，数据要求越"面"、越要签约；越往上，自建参数就够。**你们的四层网络主线覆盖 CFLP→两级→LRP→双层→仿真，所以 6 个签约包一个都省不掉。**

## 3. 精度与可靠性双重标准

### 3.1 精度（数值误差）

| 数据 | 底线精度 | 最优精度 | 为什么是这个数 |
|---|---|---|---|
| 需求点/社区质心坐标 | ±30 m | ±10 m（楼栋级） | 服务半径 300–400 m，10% 误差不误判覆盖 |
| 路网距离/时间 | 相对误差 ≤5% | ≤3%（GPS 实测校核） | 直线距离低估 20–40%，必须路网 |
| 分时段行驶时间 | ±15% | ±10% | 阻抗只用于分级，不用于精确排队 |
| 社区日件量 | ±10% | ±5% | 容量档位离散，±10% 内不跨档 |
| 分时段结构（小时曲线） | ±20% | ±15% | 只影响人力排班，不影响选址 |
| 峰值日件量/峰值系数 | ±15% | ±10% | 决定安全系数，影响投资 5–10% |
| 单点实际处理量（存量站） | ±5% | ±3% | 它是容量模型**唯一的标定基准**，必须最准 |
| 单柜周转次数/滞留时长 | ±10% / ±15% | 更低 | 直接乘出格口需求 |
| 单件处理工时 | ±15% | ±10% | 直接乘出人力配置 |
| 单车日配送单量/装载率 | ±10% | ±5% | 直接乘出车队与桩数 |
| 租金 | ±15% | ±10% | 行情区间本就宽，够用 |
| 人口 | ±5% | 官方口径 | 只做权重与公平性 |
| 自提意愿比例 | ±5 个百分点 | ±3pp | n≥400 时 95%CI 约 ±5pp |
| logit 系数 | 符号与量级正确 | ±20% | 影响使用率绝对值，不改变优选点位 |
| 格口数/面积/车位（存量） | **精确（0 误差）** | 精确 | 整数资源，错一个就是一个 |
| 无人车路权路段 | **逐段二值判定** | 不可推测 | 推测即失效，是方案硬约束 |

### 3.2 可靠性（数据本身可不可信）

七项验收标准，缺任一项该数据只能降级使用：

| 标准 | 要求 | 不达标时的处置 |
|---|---|---|
| **时间跨度** | 需求类 ≥12 个连续月，覆盖春节、618、双 11 | 降级：只用结构比例，幅值改用公开行业增速 |
| **完整性** | 关键字段缺失率 <5%，社区覆盖率 >90% | 降级：缺失区用同类社区插补并标注 |
| **口径一致** | 统一到"件"，明确件/单/票换算；退换货是否计入 | 必须解决，否则全盘不可比 |
| **空间粒度** | ≤社区（约 500 m），且能与社区边界表连接 | 低于街道级则无法支撑覆盖模型 |
| **可追溯** | 有源系统、抽取时间、口径说明文档 | 无文档视为不可用 |
| **脱敏不降维** | 去个人标识，但保留空间与时间粒度 | 只给"区级月总量"则无价值 |
| **可复算** | 能拿到同口径历史月数据用于回测 | 无法回测则结论不可验证 |

## 4. 让选址模型顺带吐出容量配置（关键改造）

### 4.1 核心思路：容量从"约束"升级为"带档位的决策变量"

传统做法把 `Q_j` 当输入常数，于是只能回答"建在哪"。改造三步：

**第一步：容量离散成可采购的规格档。**
- 柜组档位 `k ∈ {100, 200, 400, 800}` 格；驿站档位 `{60, 120, 240, 400}` ㎡（对应货架与人力）。
- 变量 `y_{jk} ∈ {0,1}`：在候选点 j 建 k 档。
- 约束 `Σ_k y_{jk} ≤ 1`（一个点只建一个档，或允许"多期叠加"时放宽）。

**第二步：容量需求由排队论反解，而不是拍系数。**
- 到达率 `λ_jt = Σ_i h_{it} x_ij / T_op`（时段 t 的件量/营业时长）。
- 服务水平约束：`P(等待 > τ) ≤ ε`，用 M/M/c 或 M/G/c 近似反解**所需服务台数**（窗口/人力）`c_j`。
- 反过来，给定档位容量，算出该点的**峰值小时通过能力**与**可承受峰值日**。

**第三步：峰值与安全系数由变异系数决定。**
```
设计容量 = 峰值小时需求 × (1 + 安全系数)
安全系数 = f(到达变异系数 CV, 服务水平 ε)   —— CV 从 D2 的分时曲线直接算
```
日均量与峰值量的比值（`峰值小时/日均小时`）必须来自真实分时数据（D2），不能拍。

### 4.2 改造后的模型骨架（可直接写进方案）

```
集合：I 需求点(社区)、J 候选点、K 规格档、T 时段(工作日/周末/大促)
参数：h_it 件量、d_ij 路网时间、f_jk 档位固定投资、cap_k 档位容量、
      μ 单台处理效率、τ 等待标准、ε 服务失败概率、S 服务半径
变量：y_jk（建不建、建多大）、x_ij（谁服务谁）、c_j（人力/窗口数）

min  Σ_j Σ_k f_jk · y_jk  +  Σ_j 运营成本(c_j, cap_k)  +  Σ 运输成本
s.t. Σ_k y_jk ≤ 1                                      （档位唯一）
     x_ij = 0  若 d_ij > S                              （覆盖半径）
     Σ_i h_it · x_ij ≤ Σ_k cap_k · y_jk   ∀t            （容量，分时段）
     c_j ≥ c*(λ_jt, μ, τ, ε)                            （排队服务水平反解）
     面积_j ≥ area(c_j, Σ_k cap_k y_jk)                  （场地可行）
     y_jk, x_ij ∈ {0,1}
```

### 4.3 输出物：一张"节点容量配置表"（这就是你们要的"顺带得出"）

| 节点ID | 类型 | 档位 | 格口/面积 | 峰值小时能力 | 日均负荷 | 峰值日负荷 | 设计利用率 | 人力 | 车位数 | 充电桩 | 无人车台数 | 扩容触发阈值 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| JD-C-07 | 社区驿站 | 240 ㎡ | 1200 格 | 420 件/h | 2,800 件 | 5,600 件 | 78% | 6 人 | 4 | 2 | 3 | 利用率 >85% 或峰值日 >6,300 件 |

**配套四类容量**（缺一类就会被问穿）：
1. **存量容量**：格口数、货架数、面积——来自 D4（精确）。
2. **通过能力**：峰值小时处理件数 = 人力 × 单件工时^-1——来自 D18（踏勘计时）。
3. **缓冲容量**：临时堆放区、爆仓容忍度——来自 D8 场地条件。
4. **周转容量**：格口 × 日周转次数——来自 D17（柜后台数据）。

**无人车台数与充电桩**（一并顺带算出）：
```
台数 N_v = ⌈ 日配送单量 × (1+冗余系数) / (单台日能力 × 可用率) ⌉      ← D19、D20
充电桩 N_c = ⌈ N_v × 单次充电时长 / 单桩日可用时长 ⌉                  ← D20
```

### 4.4 必须做的校准动作（否则容量是拍的）

用现有 427 个配送站做**回测**：把 D5 的实际峰值处理量代入模型，看模型预测容量与实际能力的偏差。
- 偏差 <10%：容量模型可用。
- 偏差 10–20%：修正单件工时或周转率后重跑。
- 偏差 >20%：说明漏了环节（如二次分拣、代收、退货暂存），补进工序表。

**这一步是整份方案里最有说服力的技术动作之一**——它证明你的容量不是估的，是校准过的。

## 5. 六个必签数据包（按可谈性排序）

| 包 | 内容 | 数据方 | 交付形态 | 谈判抓手 | 成本 |
|---|---|---|---|---|---|
| **P1 需求面** | 社区级日件量、分时曲线、峰值系数（D1–D3） | 京东物流（赛事合作方） | 脱敏聚合表（CSV，社区ID+日期+件量） | 主办方关系 + 只用于赛事、脱敏、可签保密协议 | 0 |
| **P2 存量台账** | 网点坐标/面积/格口/人力/服务范围/实际峰值量（D4–D5） | 京东物流 | 台账表 + 月报 | 同上；明确"仅用于诊断现状、不外泄" | 0 |
| **P3 路网与时段阻抗** | OD 时间矩阵、路段分时速度、限行（D6、D11–D12） | 高德/百度开放平台（付费即得）；限行取交管局公告 | API 批量结果 + 公告文本 | **无需谈判，付费即得**，这是最容易被忽略的低成本项 | 数千–数万 |
| **P4 社区边界与户数** | 小区边界、楼栋、户数、入住率（D7） | 市规自委/街道网格/物业 | 边界矢量 + 属性表 | 赛事公函 + 只取聚合户数 | 低（或免费） |
| **P5 行为标定** | 自提意愿、等待容忍、无人车接受度（D16） | **自建**问卷（社区拦截 + 线上，n≥400） | 问卷原始表 + 交叉分析 | 不需要签约 | 1–3 万 |
| **P6 运营参数** | 周转率、单件工时、单车能力（D17–D19） | **自建**踏勘 + 京东小样本 | 计时表、访谈记录 | 20–30 个点位即可 | 1–2 万 |

**注意 P3 的位置**：路网 OD 矩阵是覆盖模型和 p-中值的命门，但它是**付费即得**的商业 API，不是谈判项。很多队伍卡在这里，其实几千元就能解决。建议直接买 10 万次 OD 查询的量级。

## 6. 拿不到怎么办：每个包的 B 计划

| 包 | 拿不到时的替代路径 | 代价 |
|---|---|---|
| P1 需求面 | ① 用公开行业总量（邮政局年报）+ 人口/POI 代理变量做**分配**（不是预测总量）；② 小区级用"户数 × 渗透率 × 人均件量"估；③ 结论表述从"精确成本"改为"相对优劣与结构" | 绝对成本不可信，但点位排序基本稳住；必须在方案中明示假设 |
| P2 存量台账 | 地图 POI 抓取 + 踏勘 30 个点抽样 + 官方新闻稿中的"437 个网点/427 个配送站"总数校准 | 容量回测只能做抽样校准 |
| P3 路网 | 无 B 计划——必须买。退而求其次用 OSM + 经验速度分层 | 时间误差 20–30%，只能做定性 |
| P4 社区边界 | 用高德 POI 的"小区"类目 + 户数估算；或用街道级替代 | 覆盖粒度下降，需说明 |
| P5 行为 | 用文献先验（城市自提率 20–35%）+ 区间敏感性分析，不给点估计 | 结论加区间，可信度下降但仍成立 |
| P6 运营参数 | 用行业标准工时（快递末端分拣 60–90 件/人·小时）+ 访谈估 | 容量误差 15–20%，需标注 |

**方案写法建议**：正文只写"已获取/可获取"的数据，B 计划放进"数据可行性与风险"一节。评委看的是**你有没有想过拿不到怎么办**，而不是你有没有真的拿到。

## 9. 三条最容易踩的坑

1. **拿"区级月总量"当需求数据**。这样的数据撑不起覆盖模型，也做不了容量。必须在合同里写清"**社区级、日级**"两个粒度下限，这是谈判的核心条款，比数据量大小重要得多。
2. **用直线距离替代路网距离**。会系统性低估 20–40%，且不随机——市中心高估、郊区低估，导致点位向市中心偏。花几千元买 OD 矩阵就能消除这个偏差。
3. **容量用"日均 × 1.5"拍出来**。一旦被问"1.5 哪来的"就崩。正确做法是：分时数据算变异系数 → 排队论反解服务台数 → 得出安全系数，并做回测。
