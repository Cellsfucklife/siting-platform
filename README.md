# 末端配送节点：模糊选址中心 + 容量配置

一个两页式平台：**填表 → 结果**。输入几个数据端口（标注必填/选填），提交后
给出该片区的「模糊选址中心」与「容量配置」。

## 2. 页面与输入端口

### 页面 1：填表（`/`）

**一页填完**：左栏是必填的「小区」大文本框，右栏是四个可选数据的抽屉入口，每个入口带状态标签（未填 / 已填 N 行 / 已选文件 / 已改 N 项）。点开抽屉就地填，关掉回到本页，数据不会丢。

| # | 端口 | 标注 | 位置 | 填什么 |
|---|---|---|---|---|
| 🛜 | 输入方式 | — | 右栏顶部 | 粘贴文本 / 上传文件，切换后所有输入框同步换形态 |
| ① | 片区名字 | 可留空 | 左栏顶部 | 名称 + 位置怎么填（经纬度 / 相对米制） |
| ② | **小区** | **必填** | 左栏主体 | `小区名, 纬度, 经度, 日件量` |
| ③ | 能租的场地 | 选填 | 抽屉 | `场地名, 纬度, 经度, 面积m², 月租金[, 四项评分]` |
| ④ | 小区到场地几分钟 | 选填 | 抽屉 | `小区名, 场地名, 分钟` |
| ⑤ | **原始流水** | 选填 | 抽屉 | `小区名, 日期, 件量` + 统计口径 + 设计年 |
| ⑥ | 运行参数 | 选填 | 抽屉 | 峰值倍数、服务圈、自提比例等 8 项 |

> 第 ⑤ 项是推演层：按天/周/月/年给流水都行，平台用最小二乘拟出 `件量 = 截距 + 年趋势 + 周内系数`，
> 得到年增长率、周内系数、观测峰值系数与波动，再把②里的件量替换成**设计年日均**。
> 详见 `docs/实现逻辑.md` 的「原始流水先做一次推演」。

> 选了哪种方式，后端就**只读那种来源**：文本方式下上传的文件不参与，Excel 方式下粘贴的文本不参与
> （有残留会给一句提示）。选 Excel 却没选文件时，会直接说「你选择了上传 Excel，但还没有选择文件」，
> 并把页面停留在 Excel 方式上，不用重新点一次。

**必填实质只有两样：每个小区的位置 + 每个小区的日均件量。** 一个街道 8–20 行就能出结论。

不知道经纬度怎么办（页面上也有这三条说明）：

1. 高德/百度地图搜小区 → 右键/长按「复制坐标」，得到「纬度, 经度」两个数；
2. 把「位置怎么填」切成**相对米制**，以片区中心为原点量米数（如 `-180, 320`）；
3. 用地址批量调「地理编码」接口转成经纬度（几千次几块钱）。

精度 30 米就够（约一栋楼），因为服务圈本身是 300–400 米级别。

**8 个运行参数，只有前 3 个改结论：**

| 参数 | 大白话 | 默认 | 改了会怎样 |
|---|---|---|---|
| 大促是平常的几倍 | 峰值日/日均 | 1.6 | **影响结论**：调大更早升档 |
| 走/骑几分钟算服务圈 | 服务半径 | 10 | **影响结论**：调大 → 点更少更大 |
| 多少人愿意自提 | 自提比例 | 0.7 | **影响结论**：决定格口数 |
| 一个取件动作几秒 | 单件工时 | 45 | 窗口人力 ±1 |
| 最多容忍排多久 | 等待目标 | 180 | 窗口人力 ±1 |
| 一个配送员一天送多少件 | 车辆能力 | 160 | 车辆 ±1 |
| 末端平均骑行速度 | 换算用 | 12 | 只影响半径换算 |
| 没有件量时先估一个 | 代理件量 | 空 | 仅无②时用 |

- 分隔符支持逗号 / 制表符 / 空格，空行与 `#` 注释会被忽略。
- 纬度经度填反了会自动纠正并提示；坐标明显超范围会报错并提示改用「相对米制」。
- 行数不足或非数字会指出**第几行、错在哪一列**，已填内容不丢。
- 少于 3 个小区且没有场地时会明确提示（模型需要 ≥3 个点才算得稳）。
- 「载入示例」填入望京西 8 个小区 + 5 个场地的完整数据（`/?sample=1`）。

### Excel 上传（⓪ 选「上传 Excel / CSV」后出现）

| 项 | 说明 |
|---|---|
| 支持格式 | `.xlsx` `.xlsm` `.csv`（**不支持老式 `.xls`**，请另存为 xlsx） |
| 文件大小 | 单个 ≤ 5 MB |
| 模板下载 | 页面右上「下载 Excel 模板」→ `GET /template.xlsx`，含 4 张数据表（小区/场地/距离/流水）+ 1 张填写说明 |
| 表头 | **可有可无**，自动识别 |
| 列名 | 中英文都认：`小区名/名称/id`、`纬度/lat`、`经度/lng`、`日件量/qty` |
| 列顺序 | **能认出来就自动重排**，所以表头顺序打乱也能用 |
| 多工作表 | 自动挑名字里带「小区 / 场地 / 距离」的那张；没有就取第一个非空表 |
| 一个文件搞定 | 同一本 workbook（①小区 / ②场地 / ③距离）可以分别传到三个位置 |
| 出错提示 | 报错会带文件名，例如「场地表：「a.xlsx」里没有读到数据行」 |

### 页面 2：结果（`POST /result`）

一屏之内给全：模糊中心坐标与 r68/r90、容量档位与人力/车辆/充电桩、
示意图（内联 SVG：需求点气泡、候选三角、模糊中心星、68%/90% 圈、次峰）、
容量配置明细、交叉验证三项、方法证据、建议补的数据、原始 JSON。
顶部「返回修改」回到填表页，表单内容保留。

## 3. 结果是怎么来的

```
输入数据
  → 数据画像 L0–L3（按完备度）
  → 自动选方法：M1 连续重心 / M2 离散候选 / M3 核密度 / M4 多准则
  → 每个方法输出一张 μ(x) 隶属度场（"这个点可不可以建"）
  → 加权融合 → 唯一的模糊选址中心（中心 + 68%/90% 半径 + 多峰告警）
  → 统一容量引擎（Erlang-C 排队 + 档位选择 + 蒙特卡洛区间）→ 容量配置
  → 四层交叉验证（实现间 / 方法间 / 容量 / 单调性）→ 置信度
```

| 方法 | 依赖 | 参考实现 |
|---|---|---|
| M1 连续重心 | 需求点 | Weiszfeld 迭代 vs `scipy.optimize` |
| M2 离散候选 | + 候选点、距离矩阵 | **`spopt.locate.PMedian`** + **PuLP/CBC (CFLP)** |
| M3 核密度 | 需求点 | **`sklearn.KernelDensity`** |
| M4 多准则 | 候选点 + ≥3 准则 | 熵权-TOPSIS |

**数据越全，方法越多，置信度越高**：L3 四法融合（可高置信）、L1 两法（封顶 0.72）、
L0 单法（封顶 0.45，并提示缺什么）。

## 8. 已知限制

1. 距离默认直线×绕行系数，真路网需接高德/OSRM 或 `osmnx`。
2. 档位表是内置示例值，报绝对投资前需替换为实际台账。
3. CFLP 的固定成本是代理（`cost_index × 租金`），不是真实报价。
4. M4 无第三方等价实现，只做权重扰动，不进「实现间一致性」。
5. 容量未含二次分拣与退货暂存，峰值校准阶段需补进工序表。
6. 单进程、无数据库、无登录——本地/评审演示用；多用户需另加会话与队列。
